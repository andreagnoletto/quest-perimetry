# CLAUDE.md

Source of truth: **`SPEC.md`** (clinical product owner's specification, pt-BR). Read it before any work.
Implemented psychophysics: **`docs/CLINICAL_SPEC.md`**. Licences: **`docs/THIRD_PARTY.md`**.

## Working rules (from SPEC §0)
- Work in phases (SPEC §9). At the end of each phase: build + tests, short summary, **wait for the
  product owner's OK**.
- Anything with clinical impact: implement the HFA default, make it configurable, and **ask** before
  inventing something different. Never simplify the psychophysics silently.
- Every clinical constant lives in `config/*.json`, never in code. The config hash goes into every exam.
- Code and identifiers in English; patient/doctor UI in pt-BR (i18n ready for en-US, see
  `core/Perimetry.Core/Localization/Strings.cs`).
- Every exam logs every presentation (request + result + disposition) for audit and offline re-analysis.
- Never claim regulatory approval. Label: "Protótipo para pesquisa/uso sob supervisão médica — não registrado na ANVISA".
- Do not copy code from GPL projects (PyVF is GPL-3.0). OPI and visualFields are Apache-2.0: port with attribution.

## Layout
- `core/Perimetry.Core` — pure C# library (netstandard2.1, C# 9, only dependency Newtonsoft.Json) so the
  same sources compile in Unity 6. Namespaces: `Config`, `Geometry` (grids, Goldmann sizes, angular
  geometry), `Luminance` (dB scale, calibration), `Strategies` (ZEST, FT, fourTwo, screening, growth
  pattern), `Exam` (`ExamSession` = OPI-style server, catch trials, blind spot, records), `Analysis`
  (normative builder, TD/PD/MD/PSD/VFI/GHT, grayscale), `Simulation` (synthetic fields, observer, runner).
- `core/Perimetry.Core.Tests` — NUnit (net8.0); same tests can run in Unity Test Framework EditMode.
- `core/Perimetry.Cli` — `perimetry` CLI: simulate / analyze / benchmark / crosscheck / report (strict JSON for the
  portal) / check-calibration.
- `config/` — clinical constants and grids. `config/normative/` — provisional synthetic normative model and
  `cohort.json` (phase 6 rules for the clinic's own normative: `Analysis/Cohort.cs`, CLI `perimetry normative`).
- `tools/opi-crosscheck/` — compares C# ports with OPI in R. `tools/report/` — PNG report (matplotlib).
- `docs/regulatory/` — SRS (`REQ-*`), ISO 14971-style risk table (`HAZ-*`) and the requirement → test matrix
  generated by `tools/trace/build_matrix.py` from `traceability.json` (checked in CI; list new tests there).
- `headset/` — Unity 6 project (phase 2). `Assets/Perimetry/Logic` is pure C# (`PatientFlow` state machine,
  `PresentationTimeline`, `StimulusPlacement`, `Dither`, `ExamStorage`, `PatientMessages`, `PortalSync` sans-IO sync
  client + `LiveSnapshot`, `FixationLayout`, `GazeMonitor`, see `docs/SYNC_API.md`), tested by `headset/LogicTests`.
  `Runtime` (MonoBehaviours, head-locked rig, `GazeTracking` OpenXR eye gaze, `PortalSyncBehaviour` HTTP),
  `Resources/Perimetry` (monocular dithering shaders), `Editor` (Configure Project, config sync, Android manifest
  eye-tracking permission), `Tests/EditMode`. `/core` is a local Unity package
  (`core/Perimetry.Core/package.json`); build output goes to `/artifacts` (Directory.Build.props) so no bin/
  lands inside the package. `headset/UnityCompileCheck` compiles the Unity scripts against UnityEngine reference DLLs.
- `portal/` — doctor portal (phase 3): Next.js 15 (App Router, server actions) + PostgreSQL via Prisma.
  `src/lib` (crypto/LGPD, auth, audit, importer, `perimetry.ts` = bridge to the CLI, pdf, `headset-auth.ts` device
  tokens/pairing, `live.ts` in-process live store, `normative.ts` cohort file + clinic normative sets, `overview.ts`
  progression overview), `src/components` (`SingleFieldReport`, `OverviewReport`, SVG `FieldMaps`),
  `src/app/(app)` pages (`live/` operator panel, `normative/` cohort tool, `patients/[id]/overview`), `src/app/api/headset/*`
  (phase 4 sync API, contract in `docs/SYNC_API.md`), `src/app/api/live/*` (SSE), `src/app/print` (bare pages the PDFs print).
  The portal never computes clinical numbers: every exam goes through `perimetry report` on import.

## Commands
```bash

dotnet test headset/LogicTests                                           # 53 tests: headset flow, timing, geometry, dithering, portal sync, phase 5 modes

dotnet run --project core/Perimetry.Cli -c Release -- simulate --strategy ZestFast --defect SuperiorArcuate --seed 4 --out out/ex.json
dotnet run --project core/Perimetry.Cli -c Release -- benchmark --strategy ZestFast --runs 30
dotnet run --project core/Perimetry.Cli -c Release -- normative stats --cohort cohort.json       # phase 6: cohort rules, bands, status (JSON)
dotnet run --project core/Perimetry.Cli -c Release -- normative build --cohort cohort.json --grid 24-2 --id measured-24-2 --out db.json
dotnet run --project core/Perimetry.Cli -c Release -- report out/ex.json --normative db.json     # analyse with the clinic normative
python3 tools/report/render_report.py out/ex.analysis.json out/ex.png  # needs matplotlib
bash tools/opi-crosscheck/run.sh                                         # needs R + jsonlite, python3
python3 tools/trace/build_matrix.py                                      # regenerate + check docs/regulatory/TRACEABILITY.md
cd portal && npm ci && npm run typecheck && npm test                     # 60 portal unit tests (needs the Release CLI build)
cd portal && npm run build && npm run e2e                                # 5 Playwright specs; needs PostgreSQL (E2E_DATABASE_URL)
```
CLI options: `--grid 24-2|30-2|10-2|24-2C`, `--strategy Zest|ZestFast|FullThreshold|FourTwo|Screening`,
`--eye OD|OS`, `--defect Normal|SuperiorArcuate|InferiorArcuate|Hemianopia|CentralScotoma`, `--depth`,
`--age`, `--seed`, `--fpr`, `--fnr`, `--fixloss`, `--patient-ref`, `--fixation CentralHeijlKrakau|CentralEyeTracking|CentralUnmonitored|Oculokinetic`,
`--foveal true`, `--response YesNo|ForcedChoice`, `--gaze <simulated tracker noise sd in deg, 0 = none>`, `--config <dir>`.

## Conventions
- Field coordinates: degrees, patient's view, +x right, +y up; grids stored in OD convention, OS mirrors x.
- dB: **device dB** on the luminance increment, `10*log10(dLmax/dL)`; HFA-equivalent = device + `HfaOffsetDb`
  (≈15.5 dB nominal). Normative and grayscale use HFA-equivalent dB.
- Determinism: own PRNG (`MathUtil.Rng`, xoshiro256**), never `System.Random`.
- Ported OPI code must stay behaviour-identical: run `tools/opi-crosscheck/run.sh` after touching
  `ZestProcedure`, `FourTwoProcedure` or `FullThresholdProcedure`.
- Tests that change clinical defaults must be discussed with the product owner first.

## Clinical parameters (defaults; see config/ and docs/CLINICAL_SPEC.md)
| Item | Default |
|---|---|
| Background | 10 cd/m² (31.5 asb); nominal max 100 cd/m² until photometric calibration ("NÃO CALIBRADO") |
| Stimulus | Goldmann III (0.431°), 200 ms, white on white |
| Response window / ISI | 1000 ms / 600–1200 ms random; latency < 100 ms = anticipated (discarded) |
| ZEST | domain −5..35 dB, fpr=fnr=0.03, σ=1, bimodal prior 4:1, stop SD < 1.5 dB (fast: 2.0 dB) |
| Full Threshold | 4-2, last seen, re-test if > 4 dB from start |
| Screening | 6 dB brighter than age-expected, re-test not seen |
| Fixation | Mode A + Heijl-Krakau; blind spot (15°, −1.5°), remapped after 2 consecutive fixation losses |
| Eye tracking (phase 5, proposed) | reject threshold presentations with gaze > 3° from target at onset, retest; gaze trace recorded (modes CentralEyeTracking, Oculokinetic) |
| Oculokinetic mode B (phase 5, proposed) | target jumps uniformly in ±10°, stimulus at `AngularGeometry.Compose(target, point)`, absolute eccentricity ≤ 45°, lock 600 ms (no ET) / gaze within 3° for 300 ms (ET), HK on |
| Foveal threshold (phase 5, proposed) | optional, OFF by default; diamond-4 target (half-size 1.5°), exam strategy, before the blind-spot search; report "Limiar foveal" |
| Forced choice (phase 5, experimental) | OFF by default; 2 intervals × 200 ms, gap 600 ms, marker 100 ms; ZEST guess rate 1/N; no FP catch trials, no Heijl-Krakau; ~3× longer |
| Catch trials | FP 1/30, HK 1/30, FN 1/40 (threshold − 9 dB) |
| Alerts | FL > 20%, FP > 15%, FN > 33% |
| Indices | MD inverse-variance (Heijl 1987), PSD (Heijl 1987), GH = 85th pct, VFI (Bengtsson 2008), GHT (Åsman & Heijl 1992) |
| Normative | PROVISIONAL synthetic, HFA-eq dB, −0.7 dB/decade; phase 6 clinic cohort (`config/normative/cohort.json`): age ≥ 18, reliability within alert limits, first exam per eye dropped, latest exam per eye, MEASURED at ≥ 100 eyes |

## Headset conventions
- Stimuli are placed on a sphere centred on the TESTED eye (not the head); never in pixels.
- Clinical/presentation constants for the headset live in `config/headset.json`, `display.json`, `timing.json`.
- Phase 5: `FlowView` carries the fixation target (kind Central/Diamond4, position, lock scale/luminance, marker);
  `PresentationTimeline` runs the mode B lock (fixed delay or gaze confirmation), the forced-choice marker/interval/gap
  sequence and the per-presentation gaze statistics; `GazeMonitor`/`Runtime/GazeTracking` feed OpenXR eye gaze (Quest Pro)
  as absolute field coordinates; mode B stimuli are drawn at `AngularGeometry.Compose(target, point)`. Quest 3 = no gaze.
- The flow never shows results to the patient. Unity layer only renders `FlowView` and feeds input edges + Tick.
- Unity, the Meta XR Simulator and APK builds cannot run in the cloud container: verify those on the product
  owner's machine (or a Remote Control session).

## Portal conventions
- Identifying patient fields are AES-256-GCM encrypted (`PERIMETRY_DATA_KEY`), searchable only by exact blind index.
  Only the pseudonymous code (`P-XXXXXX`) leaves the portal (exam-order.json, research export uses a separate study ID).
- Every page/route that reads patient data calls `requireUser` and writes an `audit()` entry.
- Report shows thresholds in HFA-equivalent dB, "<NN" below the device floor; PDF is the same page printed by Chromium.
- Use TrueType fonts and plain SVG geometry in the report: Chromium turns OTF fonts and SVG `<pattern>` fills into
  megabytes of Type 3 fonts / raster images in the PDF.
- Never run `prisma migrate reset` (or anything that drops data); e2e creates a new database per run. New migrations:
  `prisma migrate diff --from-migrations prisma/migrations --to-schema-datamodel prisma/schema.prisma --shadow-database-url <empty db> --script`.
- Headset sync (phase 4): bearer token per device (SHA-256 stored), pairing code shown once; every `/api/headset/*`
  call is audited as `headset.*`. Live state is in-process (`next start` = one process) plus the `LiveSession` row;
  headset → portal is POST at 1 Hz with commands in the response, browser ← portal is Server-Sent Events.
- Phase 5 in the portal: report lines come from `src/lib/report-format.ts` (foveal line, fixation/target lines, gaze bar
  data) and `GazeTraceBar.tsx`; map geometry (`FieldMaps.geometry`) derives the lattice step per grid (6° / 2°) and a
  per-point cell so the 24-2C macular extras draw small. Exam orders carry optional `grid` / `fixationMode` /
  `fovealThreshold` / `responseMode` (docs/SYNC_API.md), written only when they differ from the preset.
- Phase 6 security/LGPD (runbook `portal/SECURITY.md`): policy constants in `src/lib/security-policy.ts` (lockout 10/15 min,
  12-char passwords, idle expiry) and `src/lib/rate-limit.ts` (per-IP, in-process); CSP nonce in `src/middleware.ts` +
  `src/lib/csp.ts`, static headers in `next.config.ts`. LGPD erasure = anonymisation (`src/lib/lgpd.ts`): never delete a
  patient row; identifiers become markers, exams stay under the code. Consent text is versioned (`src/lib/consent-text.ts`,
  bump `CONSENT_VERSION` on any wording change). Key rotation only via `scripts/rotate-key.ts`.
- Phase 6 in the portal: `Patient.normativeVolunteer` marks healthy volunteers; `lib/normative.ts` builds the pseudonymous
  cohort file (`perimetry-cohort/1`) and calls `perimetry normative stats|build` through `lib/perimetry.ts` (no rule in the
  portal); built databases live in `NormativeSet` (one active per grid). Import and re-analysis share
  `importer.analysisColumns` + `analyzeWithActiveNormative` (`--normative` when a set is active); `Exam.normativeSetId`
  records which. The report footer line comes from `report-format.normativeLine`. The progression overview
  (`lib/overview.ts`, `OverviewReport`) groups one eye's threshold exams per grid and reuses `TrendChart`; its PDF is the
  print page in A4 landscape.
